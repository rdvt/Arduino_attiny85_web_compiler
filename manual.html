MANUAL DE USO

Construye y graba firmware para ATtiny85.

Este sitio reúne tres herramientas que funcionan dentro del navegador: un ensamblador AVR, un editor de C/C++ con compilador ATtiny85 incluido y un grabador WebUSB para Digispark. No hay que instalar ningún programa ni compilador: solo abrir la página.

Todo funciona en el navegador · sin instalaciones · sin cuenta · sin servidor propio
01

Flujo completo

Escribe o carga el código

Usa el ensamblador si quieres escribir AVR directamente, o el editor si prefieres un sketch de estilo Arduino en C/C++.

Compila

El editor compila C/C++ para ATtiny85 en tu navegador. El ensamblador traduce tu programa a Intel HEX al instante.

Revisa el resultado

El sitio te dice cuánta flash usas (el máximo es 6012 bytes) y si el firmware podrá arrancar en la Digispark.

Graba la placa

Conecta la Digispark en Chrome o Edge, elige el dispositivo y espera a que termine la escritura.

Qué necesitas

HerramientaNecesitasNotas
EnsambladorCualquier navegador modernoNo usa red ni servicios externos: funciona incluso sin conexión.
Editor y compilaciónCualquier navegador modernoLa primera compilación descarga el compilador (unos 20 MB) y después queda guardado en la caché del navegador.
Grabar la placaChrome o Edge de escritorioWebUSB no existe en Safari ni en Firefox. Hace falta HTTPS o localhost.
ATtiny85 y Digispark de un vistazo: 8 KB de flash, de los que 6012 bytes quedan para tu programa (el resto es el bootloader micronucleus), y 512 bytes de RAM. El reloj es un oscilador RC interno calibrado a 16,5 MHz, así que no se necesita cristal. Los pines P3 y P4 los usa el USB por software: quedan libres P0, P1, P2 y P5.
03

Ensamblador

Escribes instrucciones AVR y obtienes el firmware. Resuelve etiquetas, valida las instrucciones y avisa de los errores antes de generar nada.

Programa mínimo, paso a paso

El ATtiny85 empieza a ejecutar en la dirección 0. Este ejemplo enciende un LED en el pin P0 y se queda encendido en un bucle:

.device attiny85
.equ DDRB = 0x17
.equ PORTB = 0x18

.org 0
rjmp reset

reset:
  ldi r16, 0x01
  out DDRB, r16
loop:
  out PORTB, r16
  rjmp loop
  1. Abre el Ensamblador.
  2. Elige el destino Digispark si vas a grabar con el bootloader micronucleus: eso limita el programa a 6012 bytes.
  3. Pulsa Ensamblar. Verás el tamaño, los símbolos y el Intel HEX.
  4. Descarga el .hex o el binario y pásalo al Flasher.
Direcciones: las etiquetas y .org usan direcciones de byte. Casi todas las instrucciones ocupan 2 bytes; JMP, CALL, LDS y STS ocupan 4. Los saltos relativos se calculan en una segunda pasada.
Directivas admitidas: .org, .byte, .word, .dword, .ascii, .asciz, .fill, .align, .equ, .set y .def. Las expresiones aceptan + - * / % << >> & | ^ ~, paréntesis y funciones como low() o high(). Las instrucciones que el ensamblador no implementa se rechazan: nunca se genera una palabra incorrecta en silencio.
04

Editor C/C++

El editor trabaja con sketches de estilo Arduino. Trae resaltado, numeración, pestañas, diagnóstico de reglas propias de ATtiny85 y el compilador del navegador.

Editar

Abre el ejemplo publicado, un archivo local o crea pestañas nuevas con + archivo. El diagnóstico se actualiza mientras escribes y marca cosas como usar Serial (el ATtiny85 no tiene puerto serie) o delay() en un sketch de ratón USB.

Compilar

Pulsa Compilar o Ctrl/⌘ + Enter. La barra muestra la flash usada y el panel separa errores y advertencias. Haz clic en un error para saltar a su línea.

Configurar un ratón

Si el sketch incluye DigiMouse.h aparece un panel para ajustar los valores del recorrido, con previsualización y presets que se aplican al código.

Descargar

Guardar descarga el archivo fuente a tu equipo. Desde ahí puedes pegarlo donde quieras; no se sube a ningún servidor.

Importante: un sketch debe tener void setup() y void loop(), y no puede definir su propio main() (ya lo pone el core). El firmware grabable debe empezar con jmp o rjmp, porque micronucleus parchea el vector de reset.
05

Compilador en el navegador

El compilador C/C++ de ATtiny85 corre dentro de la página con WebAssembly. No se instala nada en tu equipo y no se envía tu código a ningún servidor: la página descarga el compilador y lo ejecuta en tu propio navegador.

Qué compila

Objetivo digistump:avr:digispark-tiny: ATtiny85, arquitectura avr25, F_CPU de 16,5 MHz y 6012 bytes de flash de usuario. Incluye el core Digispark y sus librerías: alcanza con #include <DigiUSB.h> y el compilador busca la librería y compila sus fuentes por vos (DigiUSB, DigiKeyboard, DigiJoystick, Wire, SPI, TinyWireM, OneWire…).

Qué esperar

La primera compilación descarga unos 20 MB y puede tardar unos segundos; las siguientes son cuestión de décimas de segundo porque todo queda en la caché del navegador. Mientras compila puedes seguir moviéndote por la página: el trabajo ocurre en un hilo aparte.

Qué genera

El resultado es un Intel HEX listo para el flasher, y el del ejemplo del mouse es idéntico al que produciría la cadena oficial de Arduino para esta placa.

Cuándo no funciona

Si el módulo WebAssembly no carga (navegador muy antiguo o descarga bloqueada), el editor te lo indica. El ensamblador y el flasher siguen funcionando igual.

06

Grabar la placa

El grabador valida el firmware antes de tocar la placa —tamaño, checksum y vector de arranque— y protege el bootloader durante la operación.

  1. Abre el Flasher WebUSB en Chrome o Edge de escritorio.
  2. Selecciona tu .hex o .bin. También puedes usar el ejemplo publicado para probar.
  3. Pulsa Grabar en el ATtiny85. Chrome quedará esperando el dispositivo.
  4. Desconecta y vuelve a conectar la Digispark: el bootloader solo atiende unos 5 segundos al conectar.
  5. Elige el dispositivo 16D0:0753 en el selector.
  6. No desconectes la placa mientras se borra o se escribe la flash.
Requisitos: WebUSB no funciona en Safari ni en Firefox, y necesita HTTPS o localhost. Usa un puerto USB directo, sin hub ni dock. En Windows puede hacer falta asignar WinUSB al dispositivo con Zadig.
Si aparece “La placa no volvió a responder después del borrado”: el borrado sí se completó y el bootloader está intacto. No recargues la página. Dejá la placa desconectada, pulsa Grabar —o Grabar compilado en el editor— inmediatamente y enchúfala recién cuando Chrome esté esperando. El siguiente intento retoma la escritura sin volver a borrar.
07

Problemas frecuentes

No aparece la placa en el selector

La placa tiene que estar en modo bootloader: pulsa Grabar primero, y recién entonces desconecta y vuelve a conectar la Digispark. Tienes unos 5 segundos para elegirla. Prueba con otro cable y con un puerto USB directo.

El borrado terminó, pero aparece “La placa no volvió a responder”

Es un caso recuperable: el borrado de la flash de usuario sí terminó y el bootloader no se tocó. Dejá la placa desconectada, pulsa Grabar compilado inmediatamente y enchúfala cuando Chrome esté esperando. El segundo intento conserva el estado de borrado y continúa directamente con la escritura; no vuelve a borrar.

El botón de grabar está bloqueado

El firmware está vacío, supera los 6012 bytes o no empieza con jmp/rjmp. El panel de validación indica cuál de los tres casos es. Si el programa es demasiado grande, reduce el sketch.

La compilación falla en la primera línea con «Arduino.h no encontrado»

Falta descargar los recursos del compilador. Comprueba que la primera compilación haya terminado sin cortar la conexión y vuelve a intentar; el navegador guarda los archivos y no los vuelve a pedir.

Compila, pero el firmware no hace nada al grabar

Revisa que el destino sea Digispark (6012 bytes) y que no uses los pines P3 ni P4: están ocupados por el USB por software. Si el sketch usa DigiMouse, recuerda llamar a DigiMouse.begin().

La placa no se reenumera después de grabar

Es normal que la Digispark desaparezca y vuelva a aparecer como ratón o teclado HID: es el programa que acabas de grabar. Para grabar otra vez, repite el paso de reconectar la placa con el selector abierto.

¿Se puede usar sin internet?

El ensamblador sí, porque no usa red. El editor necesita la primera descarga del compilador; después funciona con la caché del navegador. El flasher no usa red en absoluto.

08

Ejemplos de desarrollo

Todos los ejemplos compilan en el editor C/C++ o en el ensamblador y caben en los 6012 bytes de la Digispark. Copia, pega, compila y graba.

Cómo usarlos: abre el editor, borra el sketch de ejemplo, pega el código y pulsa Compilar. Los ejemplos de ensamblador van en el ensamblador con la placa Digispark elegida.

Básicos: LED y GPIO

Blink (LED integrado)

El clásico parpadeo en P1, donde la Digispark trae su LED.

void setup() {
  pinMode(1, OUTPUT);
}
void loop() {
  digitalWrite(1, HIGH);
  delay(500);
  digitalWrite(1, LOW);
  delay(500);
}

Botón + LED

Lee un botón en P0 con pull-up y enciende el LED de P1.

void setup() {
  pinMode(0, INPUT_PULLUP);
  pinMode(1, OUTPUT);
}
void loop() {
  bool presionado = digitalRead(0) == LOW;
  digitalWrite(1, presionado);
  delay(10);
}

LED respirando (PWM)

Fade suave usando PWM por hardware en P0 o P1.

void setup() {
  pinMode(1, OUTPUT);
}
void loop() {
  for (int i = 0; i <= 255; i += 5) {
    analogWrite(1, i);
    delay(8);
  }
  for (int i = 255; i >= 0; i -= 5) {
    analogWrite(1, i);
    delay(8);
  }
}

SOS morse

Parpadea SOS en el LED integrado: tres cortos, tres largos, tres cortos.

const int LED = 1;

void punto()  { digitalWrite(LED, HIGH); delay(120); digitalWrite(LED, LOW); delay(120); }
void raya()   { digitalWrite(LED, HIGH); delay(360); digitalWrite(LED, LOW); delay(120); }

void setup() { pinMode(LED, OUTPUT); }
void loop() {
  punto(); punto(); punto();
  raya();  raya();  raya();
  punto(); punto(); punto();
  delay(1500);
}

Analógicos y PWM

Lectura analógica

Lee un potenciómetro en P2 (ADC1) y ajusta el brillo del LED.

void setup() {
  pinMode(1, OUTPUT);
}
void loop() {
  int valor = analogRead(A1);   // P2
  analogWrite(1, valor / 4);    // 0..1023 → 0..255
  delay(20);
}

Luz nocturna (LDR)

Enciende el LED sólo cuando oscurece, con una fotorresistencia en P2.

void setup() {
  pinMode(1, OUTPUT);
}
void loop() {
  bool oscuro = analogRead(A1) < 300;
  digitalWrite(1, oscuro);
  delay(100);
}

Servo básico

Mueve un servo en P1 usando pulsos de 1000–2000 µs.

void setup() {
  pinMode(1, OUTPUT);
}
void pulso(int micros) {
  digitalWrite(1, HIGH);
  delayMicroseconds(micros);
  digitalWrite(1, LOW);
}
void loop() {
  for (int pos = 1000; pos <= 2000; pos += 10) {
    pulso(pos);
    delay(20);
  }
}

Termistor NTC

Aproxima la temperatura con un NTC en P2 y enciende aviso si pasa 30 °C.

void setup() {
  pinMode(1, OUTPUT);
}
void loop() {
  int lectura = analogRead(A1);
  // NTC 10k con divisor a 5V: valor alto = más temperatura
  bool caliente = lectura > 550;
  digitalWrite(1, caliente);
  delay(500);
}

Comunicación USB (DigiKeyboard/DigiUSB)

DigiKeyboard: hola mundo

Escribe un mensaje cada 10 segundos como teclado USB.

#include <DigiKeyboard.h>

void setup() { }
void loop() {
  DigiKeyboard.sendKeyStroke(0);
  DigiKeyboard.print("Hola desde ATtiny85");
  DigiKeyboard.delay(10000);
}

Contraseñita rápida

Escribe una cadena y presiona Enter (útil para autologin de prueba).

#include <DigiKeyboard.h>

void setup() { }
void loop() {
  DigiKeyboard.sendKeyStroke(0);
  DigiKeyboard.print("mi-contrasena-de-prueba");
  DigiKeyboard.sendKeyStroke(KEY_ENTER);
  DigiKeyboard.delay(30000);
}

DigiUSB: eco

Recibe un byte por DigiUSB y lo devuelve (requiere la app de escritorio).

#include <DigiUSB.h>

void setup() { DigiUSB.begin(); }
void loop() {
  if (DigiUSB.available()) {
    DigiUSB.write(DigiUSB.read());  // eco
  }
  DigiUSB.refresh();
}

Notas musicales

Genera tonos en P1 con tone() (el LED integrado suena poco: usa un buzzer).

const int BUZZER = 1;

void setup() { pinMode(BUZZER, OUTPUT); }
void nota(int frec, int ms) {
  tone(BUZZER, frec, ms);
  delay(ms * 1.3);
}
void loop() {
  nota(262, 300);  // DO
  nota(294, 300);  // RE
  nota(330, 300);  // MI
  nota(349, 300);  // FA
  nota(392, 500);  // SOL
  delay(1000);
}

Mouse USB con DigiMouse

Mouse jiggler

Mueve el cursor un píxel cada 20 ms para evitar el bloqueo por inactividad.

#include <DigiMouse.h>

void setup() { DigiMouse.begin(); }
void loop() {
  DigiMouse.moveX(1);
  DigiMouse.delay(20);
  DigiMouse.moveX(-1);
  DigiMouse.delay(20000);
}

Círculo completo

Mueve el cursor en círculos pequeños usando seno y coseno.

#include <DigiMouse.h>

void setup() { DigiMouse.begin(); }
void loop() {
  for (int grados = 0; grados < 360; grados += 10) {
    float rad = grados * 3.14159 / 180.0;
    char dx = (char)(cos(rad) * 5.0);
    char dy = (char)(sin(rad) * 5.0);
    DigiMouse.move(dx, dy, 0);
    DigiMouse.delay(20);
  }
}

Clic cada minuto

Simula presencia con un clic (usa setButtons, no leftClick()).

#include <DigiMouse.h>

// Máscaras de botones: 1=izquierdo, 2=derecho, 4=central
void clic() {
  DigiMouse.setButtons(1);
  DigiMouse.delay(20);
  DigiMouse.setButtons(0);
  DigiMouse.delay(20);
}

void setup() { DigiMouse.begin(); }
void loop() {
  clic();
  DigiMouse.delay(60000);
}

Mouse + teclado juntos

NO se pueden mezclar: elige uno. Este ejemplo documenta el error típico.

// ERROR común: los dos definen el mismo descriptor USB.
// #include <DigiMouse.h>    // elige mouse...
// #include <DigiKeyboard.h> // ...o teclado, pero no ambos.
// El editor te avisa si intentas usar los dos.
#include <DigiMouse.h>

void setup() { DigiMouse.begin(); }
void loop() {
  DigiMouse.move(3, 0, 0);
  DigiMouse.delay(20);
  DigiMouse.move(-3, 0, 0);
  DigiMouse.delay(20);
}

Ensamblador AVR

LED parpadeando

El blink en assembler puro, listo para el ensamblador del sitio.

.device attiny85
.equ DDRB = 0x17
.equ PORTB = 0x18
.org 0
rjmp inicio
inicio:
  ldi r16, 2      ; P1 como salida
  out DDRB, r16
bucle:
  ldi r16, 2
  out PORTB, r16  ; LED on
  ldi r17, 30
  rcall pausa
  ldi r16, 0
  out PORTB, r16  ; LED off
  ldi r17, 30
  rcall pausa
  rjmp bucle
pausa:
  ldi r18, 0
pausa2:
  dec r18
  brne pausa2
  dec r17
  brne pausa
  ret

Contador binario en P0..P2

Cuenta 0..7 en tres LEDs conectados a P0, P1 y P2.

.device attiny85
.equ DDRB = 0x17
.equ PORTB = 0x18
.org 0
rjmp inicio
inicio:
  ldi r16, 0b00000111
  out DDRB, r16   ; P0..P2 salidas
  ldi r17, 0      ; contador
bucle:
  out PORTB, r17
  ldi r18, 25
  rcall pausa
  inc r17
  andi r17, 0x07
  rjmp bucle
pausa:
  ldi r19, 0
pausa2:
  dec r19
  brne pausa2
  dec r18
  brne pausa
  ret

Lectura de botón (PINB)

Refleja el estado de un botón en P0 al LED de P1.

.device attiny85
.equ DDRB = 0x17
.equ PORTB = 0x18
.equ PINB = 0x16
.org 0
rjmp inicio
inicio:
  ldi r16, 0b00000010
  out DDRB, r16   ; P1 salida, P0 entrada
  ldi r16, 1
  out PORTB, r16  ; pull-up en P0
bucle:
  in r17, PINB
  bst r17, 0      ; bit de P0 → T
  bld r18, 1      ; T → bit de P1
  andi r18, 0b00000010
  out PORTB, r18
  rjmp bucle

PWM por software

Genera un fade de LED por software en P0 (sin PWM de hardware).

.device attiny85
.equ DDRB = 0x17
.equ PORTB = 0x18
.org 0
rjmp inicio
inicio:
  ldi r16, 1
  out DDRB, r16   ; P0 salida
  ldi r24, 0      ; brillo 0..255
bucle:
  out PORTB, r24  ; encendido proporcional
  ldi r20, 4
  rcall pausa
  eor r24, r24    ; simplificado: parpadeo lento
  inc r24
  rjmp bucle
pausa:
  ldi r21, 0
pausa2:
  dec r21
  brne pausa2
  dec r20
  brne pausa
  ret

Avanzados

Dormir y despertar

Usa el modo power-down y el watchdog para ahorrar batería.

#include <avr/sleep.h>
#include <avr/wdt.h>

void setup() {
  pinMode(1, OUTPUT);
  set_sleep_mode(SLEEP_MODE_PWR_DOWN);
}
void loop() {
  digitalWrite(1, HIGH);
  delay(10);
  digitalWrite(1, LOW);
  // duerme 8 s con el watchdog
  wdt_enable(WDTO_8S);
  sleep_mode();
  wdt_disable();
}

EEPROM interna

Guarda un contador en EEPROM que sobrevive a los reinicios.

#include <EEPROM.h>

int direccion = 0;

void setup() {
  pinMode(1, OUTPUT);
  int valor = EEPROM.read(direccion);
  for (int i = 0; i < valor && i < 15; i++) {
    digitalWrite(1, HIGH); delay(80);
    digitalWrite(1, LOW);  delay(80);
  }
}
void loop() {
  int valor = EEPROM.read(direccion);
  if (valor < 15) EEPROM.write(direccion, valor + 1);
  delay(60000);
}

I²C esclavo mínimo

Responde a direcciones I²C con TinyWireS (librería externa).

// Requiere la librería TinyWireS instalada.
// En la Digispark: P0 = SDA, P2 = SCL.
#include <TinyWireS.h>

#define PROPIA_DIR 0x08

void setup() {
  TinyWireS.begin(PROPIA_DIR);
}
void loop() {
  if (TinyWireS.available()) {
    TinyWireS.send(TinyWireS.receive() + 1);  // eco +1
  }
}

Random con semilla analógica

Genera aleatoriedad leyendo ruido en un pin flotante.

void setup() {
  pinMode(1, OUTPUT);
  randomSeed(analogRead(A1));
}
void loop() {
  int parpadeos = random(1, 6);
  for (int i = 0; i < parpadeos; i++) {
    digitalWrite(1, HIGH); delay(60);
    digitalWrite(1, LOW);  delay(60);
  }
  delay(random(500, 3000));
}

Publicar este sitio

Esta sección es para quien administra el sitio, no para usarlo. Si solo quieres compilar y grabar tu ATtiny85, ya está todo explicado arriba.

El sitio es 100 % estático y se sirve desde la raíz del repositorio. En GitHub Pages se publica solo: el workflow .github/workflows/pages.yml empaqueta la raíz y la despliega con cada push a main. Para probarlo en tu equipo alcanza con el servidor del repositorio, que publica el sitio bajo el mismo subdirectorio que GitHub Pages (y con las mismas reglas: omite los archivos ocultos, sirve index.html en las carpetas y usa los tipos MIME del hosting):

node tools/servir-local.mjs
# abre http://127.0.0.1:8000/Arduino_attiny85_web_compiler/editor/

# o, más simple, cualquier servidor estático desde la raíz:
python3 -m http.server 8000
# abre http://localhost:8000/

Contenido de la raíz:

├── index.html       ← portada
├── manual.html      ← este manual
├── assembler/       ← ensamblador AVR en el navegador
├── editor/          ← editor C/C++
├── compiler/        ← compilador ATtiny85 en WebAssembly
├── flasher/         ← grabación WebUSB
├── build/           ← firmware HEX de ejemplo
├── DigisparkMouse/  ← sketch de ejemplo
├── wasm/            ← inventario documentado del toolchain
├── vendor/three/    ← three.js local (sin CDN)
└── .nojekyll        ← evita que GitHub Pages omita los assets del compilador
No sirve abrirlo con doble clic: el sitio usa módulos de JavaScript y WebAssembly, así que necesita servirse por HTTP (o HTTPS). Publicarlo en cualquier hosting estático es suficiente.
