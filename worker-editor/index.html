Integración

Del editor al chip, sin piezas sueltas

El agente local corre cc1plus, avr-as, avr-ld y avr-objcopy con arduino-cli y el core digistump:avr instalados en tu máquina. El compilador WebAssembly de /editor/ produce el mismo Intel HEX sin instalar nada. Después ese HEX entra por WebUSB o por arduino-cli upload.

RequisitoPor quéCómo verificar

            3 · Instalación paso a paso

            

              Atajo: bajá
              ⬇ tools.zip
              y descomprimilo en la raíz del repo. Adentro está todo
              tools/ —el agente, los scripts de verificación y el
              README.md con los requisitos y el uso— así que no hace falta copiar
              archivo por archivo. Después seguí con el paso 4 para levantarlo.
              

              Lo único imprescindible para que esta página funcione es
              tools/compile-agent.py.
            


            
macOS (Homebrew)

            
# 1. Python 3: macOS ya trae python3
python3 --version

# 2. arduino-cli
brew install arduino-cli

# 3. Los dos cores que hacen falta
arduino-cli core update-index
arduino-cli core install arduino:avr
arduino-cli core install digistump:avr


            
Linux

            
# 1. Python 3 (viene con la mayoría de las distros)
python3 --version

# 2. arduino-cli con el instalador oficial
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
sudo install -m 755 bin/arduino-cli /usr/local/bin/arduino-cli
arduino-cli version

# 3. Los dos cores
arduino-cli core update-index
arduino-cli core install arduino:avr
arduino-cli core install digistump:avr


            
Si digistump:avr no aparece

            

              Significa que falta el board index de Digistump en la lista de URLs adicionales. El oficial es
              http://digistump.com/package_digistump_index.json y el sitio suele estar caído;
              el mirror verificado en GitHub sirve la misma versión 1.6.7:
            

            
arduino-cli config add board_manager.additional_urls \
  https://raw.githubusercontent.com/digistump/arduino-boards-index/master/package_digistump_index.json
arduino-cli core update-index
arduino-cli core install digistump:avr
arduino-cli core list   # tiene que mostrar digistump:avr


            
Comprobar el entorno nativo (opcional, para WASM)

            
bash tools/check-wasm-toolchain.sh

            

              Sólo hace falta si vas a reconstruir el toolchain WebAssembly. Para esta página
              (agente local) no es necesario: el agente compila con el avr-gcc del core instalado.

            5 · Servir el sitio y abrir esta página
            

              El agente es un servicio aparte: la página se sirve como cualquier archivo estático. Dos terminales:
            

            
# terminal 1 (raíz del repo)
python3 -m http.server 8000

# terminal 2 (raíz del repo)
python3 tools/compile-agent.py

            
Y abrí en Chrome o Edge:

            
http://localhost:8000/worker-editor/

            

              Funciona igual desde GitHub Pages (https://rdvt.github.io/Arduino_attiny85_web_compiler/worker-editor/):
              Chrome permite que una página HTTPS llame a http://127.0.0.1 porque lo trata como origen confiable.
              Si usás otro dominio, arrancá el agente con --allow-origin.
            

          


          

            6 · Cómo se usa el editor, paso a paso
            
    
              
  1. 1Confirmá el chip de arriba a la derecha: Agente OK. Si dice “sin respuesta”, el paso 4 no está hecho.
    2. 
              
  2. 2Elegí la placa. Para Digispark: digistump:avr:digispark-tiny (Default 16.5 MHz).
    3. 
              
  3. 3Editá el código. El nombre del sketch define el .ino y el .hex resultante.
    4. 
              
  4. 4Pulsá Compilar (Ctrl/⌘+⏎). El panel derecho muestra flash/RAM, errores y el HEX.
    5. 
              
  5. 5Bajá el .hex (o el .bin) para grabarlo con otra herramienta.
    6. 
              
  6. 6Para grabar elegí uno de los dos caminos:
                Grabar desde la máquina (recomendado: usa arduino-cli, sin WebUSB — ver paso 7)
                o Grabar, que abre el selector WebUSB de Chrome para elegir 16D0:0753.
    7. 
            

            

              Guardar escribe el archivo dentro del repo a través del agente (deja un .bak antes).
              abrir del repo lista los fuentes que el agente puede leer.
            

          


          

            7 · Grabar desde la máquina, sin WebUSB (lo más confiable)
            

              El agente corre en tu máquina, así que puede grabar con el mismo camino que el IDE de Arduino:
              arduino-cli llama al CLI de micronucleus (recetas
              tools.micronucleus.* del core Digistump), que se queda esperando hasta 60 s a que
              la placa aparezca en modo bootloader. No pasa por Chrome, ni por WebUSB, ni necesita permisos de USB.
            

            

              El orden importa: pulsá Grabar desde la máquina y recién entonces
              reenchufá la placa. El bootloader micronucleus sólo escucha ~5 s después de conectarse; si la enchufás antes
              de pulsar, el agente nunca la ve.
            

            
Por comando, sin la página (equivale a pulsar el botón):

            
# 1. Compilar a un directorio de salida
arduino-cli compile --fqbn digistump:avr:digispark-tiny --output-dir build DigisparkMouse

# 2. Grabar (queda esperando la placa: reenchufala cuando lo veas)
arduino-cli upload -p usb --fqbn digistump:avr:digispark-tiny --input-dir build DigisparkMouse

            

              La salida esperada de una grabación buena termina con
              >> Micronucleus done. Thank you! y muestra antes
              > Device has firmware version 1.6 y
              > Available space for user applications: 6012 bytes.
            

            

              Por HTTP, si querés scriptearlo:
            

            
curl -s -X POST http://127.0.0.1:8765/upload \
  -H 'content-type: application/json' \
  -d "$(python3 -c 'import json;print(json.dumps({"source": open("DigisparkMouse/DigisparkMouse.ino").read(), "name": "DigisparkMouse", "fqbn": "digistump:avr:digispark-tiny"}))')" \
  | python3 -m json.tool

            

              Ojo con un detalle de arduino-cli: devuelve exit 0 aunque micronucleus falle
              (el timeout de búsqueda de placa no se propaga). Por eso el agente decide el resultado leyendo el log y
              buscando Micronucleus done, no el código de salida.
            

            

              Si la placa no aparece, el agente lo dice claro y no toca nada: la flash de usuario queda intacta.
            

          


          

            8 · Endpoints del agente (para scriptear o depurar)
            

              
Método y rutaQué devuelve

              
GET /healtharduino-cli, dataDir, cores, digistumpInstalled y la lista de placas ATtiny85 detectadas.

              
GET /boardsPlacas ATtiny85 con fqbn, fCpu, maximumSize y usesUsb.

              
GET /filesFuentes del repo que se pueden abrir/editar.

              
GET /sketch?path=<rel>Contenido de un archivo del repo.

              
POST /compileBody { source, name, fqbn, files[] } → { ok, hex, bytes, sizes, files, log, error }.

              
POST /uploadBody { source, name, fqbn, files[], port? } → compila y graba con arduino-cli. Espera hasta 60 s a la placa. Devuelve { ok, stage, bytes, log, error }.

              
POST /saveBody { path, source } → guarda con backup .bak.

            

            
Prueba rápida sin navegador:

            
curl -s http://127.0.0.1:8765/health | python3 -m json.tool

            10 · Problemas frecuentes
            

              
SíntomaCausa y solución

              
“No pude hablar con el agente en http://localhost:8765”El agente no está levantado o está en otro puerto. Levantalo (paso 4) y abrí nuevamente la URL normal del Worker Editor; no hace falta agregar parámetros.

              
HTTP 403 “origen rechazado”Servís el sitio en un dominio que no está en la lista blanca. Arrancá el agente con --allow-origin http://tu-host:8000.

              
“No encuentro 'arduino-cli'” en la consola del agenteNo está en el PATH del proceso: instalalo o pasá --arduino-cli /ruta/completa.

              
Compila pero falla con Arduino.h o DigiMouse.hFalta el core. arduino-cli core list tiene que mostrar digistump:avr (ver paso 3).

              
Error de avr-gcc en Apple SiliconEl agente ya reemplaza el compilador i386 de Digistump por el de arduino:avr. Si igual falla, instalá arduino:avr 1.8.8.

              
El puerto 8765 está ocupadopython3 tools/compile-agent.py --port 9000 y, sólo en ese caso, abrí la página con ?agent=http://localhost:9000.

              
Grabar dice “no se encontró el dispositivo”El bootloader micronucleus escucha ~5 s: pulsá Grabar, desconectá la placa y volvé a enchufarla con el diálogo abierto. Puerto USB directo, sin hub.

              
Grabar por WebUSB se queda en “Esperando a que la placa se reenumere”El borrado deja a Chrome sin handle válido en algunos hosts. Usá Grabar desde la máquina (paso 7): por arduino-cli no pasa. Si no, pulsá Grabar otra vez y reenchufá la placa: ese intento ya no vuelve a borrar y escribe directo.

              
“MICRONUCLEUS device seems to be inactive”El bootloader quedó a medio responder: desenchufá, pulsá Grabar y volvé a enchufarla.
