Flasher WebUSB · Digispark ATtiny85

Graba el firmware en la placa desde Chrome, sin instalar nada: habla el protocolo micronucleus por WebUSB. Valida el archivo antes de escribir y protege el bootloader para poder reintentar si algo falla.

Comprobando el navegador…

1 · Firmware

Buscando build/DigisparkMouse.ino.hex…

2 · Grabación

Pulsa Grabar: se abre el diálogo de Chrome (queda escuchando), desconecta la placa y vuelve a conectarla; después selecciónala en la lista. El bootloader sólo escucha ~5 segundos desde que la conectás.

Opciones avanzadas

Si la grabación falla en la primera página con un timeout, prueba Forzar v2: algunos clones baratos reportan una versión vieja pero hablan el protocolo nuevo.

Tutoriales minuciosos

      

        

          A · Preparar y validar el firmware
          
    
            
  1. Compila tu sketch en el Editor y pulsa Grabar compilado, o usa Elegir archivo para cargar un .hex/.bin que ya tengas (por ejemplo, el del Ensamblador).
    2. 
            
  2. Esperá a que aparezca el tamaño y el vector de reset. Debe ser jmp o rjmp.
    3. 
            
  3. El límite de Digispark es 6012 bytes de flash de usuario; si se supera, el botón de grabar queda bloqueado.
    4. 
            
  4. No cierres esta pestaña durante el proceso: el log explica cada reenumeración USB.
    5. 
          

        

        

          B · Entrar al bootloader a tiempo
          
    
            
  1. Usa Chrome o Edge de escritorio en https:// o localhost. Safari y Firefox no sirven para WebUSB.
    2. 
            
  2. Preferí un puerto directo y un adaptador USB-C→USB-A pasivo; evitá hubs y docks.
    3. 
            
  3. Pulsa Grabar en el ATtiny85 y deja abierto el diálogo del navegador.
    4. 
            
  4. Desconecta y conecta la placa mientras el diálogo escucha. Elige 16D0:0753 antes de que pasen aproximadamente 5 segundos.
    5. 
          

        

        

          C · Interpretar el progreso
          
    
            
  1. Borrando: sólo se borra la zona de usuario; micronucleus permanece intacto.
    2. 
            
  2. Reenumerando: es normal que el dispositivo desaparezca y vuelva a aparecer.
    3. 
            
  3. Grabando: no muevas ni desconectes la placa.
    4. 
            
  4. Arrancando: el dispositivo deja de ser WebUSB y vuelve a aparecer como mouse HID.
    5. 
          

        

        

          D · Recuperarse de un error
          
    
            
  • Si el selector no muestra nada al comenzar, dejá la placa desconectada, pulsa Grabar y recién entonces conecta la placa; el bootloader sólo escucha unos 5 segundos.
    • 
            
  • Si aparece “La placa no volvió a responder después del borrado”: el borrado sí se completó. No recargues la página ni vuelvas a iniciar otro flujo: dejá la placa desconectada, pulsa Grabar inmediatamente y enchúfala cuando Chrome esté esperando. El siguiente intento retoma la escritura y no vuelve a borrar.
    • 
            
  • Si falla la primera página, prueba Forzar v2 en Opciones avanzadas.
    • 
            
  • En Windows, asigná WinUSB al dispositivo 16d0:0753 con Zadig. En Linux, instalá las reglas udev de micronucleus.
    • 
          

        

      

    


    

      
    
        
  • Chrome o Edge de escritorio, en https:// o localhost, y abierto como página normal (no dentro de un webview).
    • 
        
  • Sólo se puede grabar en modo bootloader. Con el firmware corriendo, la placa es un mouse HID y Chrome no da acceso a dispositivos HID.
    • 
        
  • Después del borrado la placa se reenumera. El log lo muestra; si nunca vuelve, el bootloader sigue intacto (sólo se borra la flash de usuario). Dejá la placa desconectada, pulsa Grabar inmediatamente y vuelve a enchufarla cuando Chrome esté esperando: el próximo intento continúa con la escritura sin volver a borrar.
    • 
        
  • Windows: Chrome necesita WinUSB para 16d0:0753. Si aparece Access denied, apuntá ese dispositivo a WinUSB con Zadig (el driver de Digistump/libusbK no sirve para WebUSB).
    • 
        
  • Linux: hacen falta las mismas reglas udev que usa micronucleus (49-micronucleus.rules) para que Chrome pueda abrir el dispositivo.
    • 
        
  • Puerto directo, sin hub ni dock. V-USB es bit-bang por software: detrás de un hub USB 3.x las escrituras se cortan a la mitad.
